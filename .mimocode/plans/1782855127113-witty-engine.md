# Переработка: «Математический навигатор» в Doodle Jump

## Суть

Кот прыгает вверх, а над ним **живой пример**, который меняется ПОСЛЕ КАЖДОГО правильного прыжка. Ребёнок решает задачи на лету, не останавливаясь.

## Механика (пошагово)

### 1. Старт: Брифинг
```
┌─────────────────────────────────┐
│  🐱 Кот-учёный                 │
│  Мур! Давай решать примеры!     │
│  Прыгай на правильный ответ!    │
│                                 │
│  ┌─────────────────────────────┐│
│  │   5 + 4 = ?                ││
│  │   ┌───┐ ┌───┐ ┌───┐       ││
│  │   │ 8 │ │ 9 │ │10 │       ││  ← 3-4 платформы
│  │   └───┘ └───┘ └───┘       ││
│  └─────────────────────────────┘│
│                                 │
│  🚀 Поехали!                   │
└─────────────────────────────────┘
```

### 2. Игра: Непрерывный подсчёт
```
  5 + 4 = ?           ← пример над котом
       ┌───┐
       │ 9 │ ← правильный ответ (буст!)
  ┌───┐     ┌───┐
  │ 8 │     │10 │
  └───┘     └───┘
       🐱           ← кот прыгает на 9
        ↓
  12 - 3 = ?         ← НОВЫЙ пример сразу!
  ┌───┐ ┌───┐ ┌───┐
  │ 7 │ │ 9 │ │11 │
  └───┘ └───┘ └───┘
```

### 3. Правила прыжков

| Ситуация | Что происходит |
|----------|---------------|
| **Прыжок на правильный ответ** | 💥 Буст +16, новый пример мгновенно, +1 очко |
| **Прыжок на неправильный** | ⬇️ Слабый отскок, платформа ломается, пример ОСТАЁТСЯ (попробуй снова) |
| **Все платформы неправильные** | Кот падает → Game Over |

### 4. Задания (генерируются на лету)

**Математика (1-4 класс ФГОС):**
- Сложение: `5 + 4 = ?` → ответ: 9
- Вычитание: `12 - 3 = ?` → ответ: 9
- Умножение: `3 × 4 = ?` → ответ: 12
- Уравнение: `x + 7 = 15` → ответ: 8
- Сравнение: `Как больше: 15 или 18?` → ответ: 18

**Русский язык:**
- ЖИ/ШИ: `Заполни: ЖИ___А` → буквы: Р, Ы, Ш, П → ответ: Р
- Пропуск: `КОН___ (с мягкий знаком)` → ответ: Ь
- Ударения: `Где верное ударение: ПРАВИльный?` → ответ: да/нет

### 5. Сложность растёт

| Этаж (очки) | Диапазон примеров |
|------------|-------------------|
| 0-5 | Сложение в пределах 10 |
| 5-10 | Сложение/вычитание в пределах 20 |
| 10-20 | Умножение до 10×10 |
| 20-30 | Уравнения |
| 30+ | Смешанные, быстрые |

## Файлы для изменения

| Файл | Что меняется |
|------|-------------|
| **`FGOSDoodlePhysics.ts`** | `FGOSGameConfig` → добавить `question`, `options[]`, `correctIndex`. При прыжке на правильную → `onCorrect()` callback. При неправильной → `onWrong()` |
| **`FGOSDoodleRenderer.ts`** | HUD: рисовать пример в центре над котом (animated text). Правильная платформа пульсирует зелёным |
| **`FGOSConfig.ts`** | Новый генератор: `generateLiveTask(subject, difficulty)` → `{ question, options, correctAnswer }` |
| **`FGOSDoodleGame.tsx`** | State: текущий пример, при правильном прыжке → генерировать новый. Брифинг показывает первый пример |
| **`App.tsx`** | Game over → `onReward(reward)` → `addGems(gems)` + обновление прогресса ФГОС |

  } else {
    // Russian: заполни пропуск, найди правильное слово
  }

## Поток запуска

1. **Брифинг** → Кот: «Реши пример и прыгни на ответ! Пример: 5 + 4 = ?»
2. **Игра** → Пример над котом, 3-4 платформы, правильный ответ = буст + новый пример
3. **Game Over** → Подсчёт: сколько примеров решено, верность, очки
4. **Награда** → `calculateLessonReward()` → монеты в общий баланс

## 1. Архитектура данных ФГОС

### Принцип: дерево, которое является «единым источником правды»

Каждый узел дерева ФГОС управляет сразу тремя подсистемами:
- **Генератором задач** (какие параметры передавать AI/генератору)
- **Блокировкой комиксов** (какие главы сюжета требуют этой темы)
- **Спавном препятствий** (какие типы заданий становятся препятствиями в раннере)

```typescript
// core/fgos/fgos-tree.ts — чистая структура данных, без React

interface FGOSGrad {
  grade: 1 | 2 | 3 | 4;
  label: string;                  // "1 класс"
  quarters: FGOSQuarter[];
}

interface FGOSQuarter {
  quarter: 1 | 2 | 3 | 4;
  label: string;                  // "I четверть"
  topics: FGOSTopic[];
}

interface FGOSTopic {
  id: string;                     // "add_1_10"
  name: string;                   // "Сложение в пределах 10"
  subject: "math" | "russian";
  icon: string;                   // "➕"
  color: string;                  // "#3B82F6"

  // === Подсистема генератора задач ===
  generatorId: string;            // ключ в реестре генераторов
  generatorParams: {              // параметры, передаваемые в AI/генератор
    numberRange: [number, number];
    operators?: string[];
    maxOperands?: number;
  };
  templateHint: string;           // "Котик советует: посчитай на пальчиках! 🐾"

  // === Подсистема блокировки комиксов ===
  gatesChapterIds: string[];      // какие главы комиксов разблокирует

  // === Подсистема спавна препятствий ===
  obstacleType: string;           // "choice" | "input" | "quick-math"
  obstacleDifficulty: 1 | 2 | 3; // влияет на скорость/сложность в раннере

  // === Прогрессия ===
  prerequisites: string[];        // ID тем, которые нужны перед этой
  progressToComplete: number;     // сколько XP нужно для завершения

  // === Адаптивность ===
  olympiadVariantId: string | null; // ID олимпиадного варианта для одарённых
}

// AI Structured Output JSON Schema (для будущей Gemini API)
interface AIStructuredTask {
  catNarrative: string;           // "Мур! Помоги коту решить..."
  question: string;               // текст задания
  options: [string, string, string, string];  // ровно 4 варианта
  correctIndex: 0 | 1 | 2 | 3;
  catHint: string;                // "🐱 Мур-подсказка: вспомни правило..."
  explanation: string;
  difficulty: number;             // 1–5
  tags: string[];                 // ["сложение", "1 класс", "I четверть"]
}
```

**Почему это решение:**
- Одна структура правит тремя подсистемами — нет рассинхронизации
- `prerequisites` создают DAG (направленный ациклический граф) зависимостей — естественная блокировка
- `olympiadVariantId` — точка входа для адаптивной сложности
- `AIStructuredTask` — контракт для будущего Gemini API (Structured Outputs)

**Конкретные файлы:**
- `src/core/fgos/fgos-tree.ts` — типы и интерфейсы
- `src/core/fgos/math-grades.ts` — дерево ФГОС Математика (1–4 классы)
- `src/core/fgos/russian-grades.ts` — дерево ФГОС Русский язык (1–4 классы)
- `src/core/fgos/progression.ts` — чистые функции разблокировки, проверки зависимостей

## 2. Изоляция бизнес-логики (слой `core/`)

### Проблема сейчас:
`useGameState()` (state.ts) — это 389 строк, где смешаны:
- Чистая логика (подсчёт монет, проверка ачивок)
- Персистенция (localStorage)
- Побочные эффекты (DOM-темы, setInterval для кота)
- React-хуки (useState, useEffect, useCallback)

### Решение: трёхслойная архитектура

```
src/
├── core/              ← PURE TypeScript (0% React, 0% DOM)
│   ├── fgos/          ← ФГОС: дерево тем + прогрессия + блокировки
│   ├── economy/       ← Экономика: формулы монет, магазин, цены
│   ├── player/        ← Игрок: стейт профиля, кот, ачивки
│   ├── tasks/         ← Генерация заданий (AI-ready)
│   ├── stories/       ← Сюжетная кампания (главы, замки)
│   └── index.ts       ← публичное API слоя
│
├── adapters/          ← BRIDGE: React-хуки над core (usePlayer, useEconomy...)
│   ├── use-player.ts
│   ├── use-economy.ts
│   ├── use-fgos.ts
│   └── use-cat.ts
│
├── ui/                ← PURE React (только верстка, без бизнес-логики)
│   ├── screens/       ← Экраны: HomeScreen, LessonScreen, ...
│   ├── games/         ← Игровые компоненты (3D-раннер, 2D-аркады)
│   └── shared/        ← Button, Card, Progress, TopBar, BottomNav
│
├── engine/            ← Игровые движки (вне React-дерева, но внутри проекта)
│   ├── three/         ← Three.js / R3F сцены
│   │   └── cat-room/  ← 3D-комната кота (раннер — позже, за скобками MVP)
│   └── matter/        ← Matter.js 2D-физика
│       ├── red-ball/
│       └── doodle/
│
├── storage/           ← Абстракция персистенции
│   ├── types.ts       ← Интерфейс StorageAdapter
│   ├── localStorage.ts ← Текущая реализация
│   └── indexeddb.ts   ← Будущая (для больших данных AI-генераций)
│
└── app/               ← СБОРКА: App.tsx (тонкий, только композиция экранов)
```

### Ключевое правило:
>`core/` NEVER imports from React, React DOM, or any UI library.
>`ui/` NEVER contains business logic formulas — only props → JSX.
>`adapters/` — единственное место, где React-хуки встречаются с `core/`.

### Конкретный пример: подсчёт монет за урок

```typescript
// core/economy/gems.ts — чистая функция (тестируется без React)
export function calculateLessonReward(correct: number, total: number): number {
  const base = correct * 5;
  const perfectBonus = (correct === total) ? 25 : 0;
  return base + perfectBonus;
}

// adapters/use-economy.ts — React-хук
export function useEconomy() {
  const [gems, setGems] = useState(loadGems());
  const addGems = useCallback((amount: number) => {
    setGems(prev => {
      const next = prev + amount;
      saveGems(next);
      return next;
    });
  }, []);
  return { gems, addGems };
}

// ui/screens/LessonScreen.tsx — только верстка
function LessonScreen({ onFinish }: Props) {
  const { addGems } = useEconomy();
  // onFinish вызывает calculateLessonReward → addGems
}
```

## 3. Игровые инструменты — рекомендация

| Тип игры | Движок | Почему |
|----------|--------|--------|
| **3D-раннер** (Subway Surfers) | React Three Fiber + кастомная физика | Экспериментальная фича — **за скобками MVP**. Когда вернёмся: R3F даст декларативный React-API для Three.js. Императивный game loop внутри `useFrame`. |
| **2D-аркады** (Red Ball, Doodle Jump) | **Matter.js** + HTML5 Canvas | Matter.js — чистый физический движок без привязки к рендереру. Идеально для 2D-столкновений и гравитации. Рендеринг — через Canvas API (уже используется в DoodleCat.tsx). Phaser избыточен (тащит свой рендерер, аудио, сцены). |
| **3D-комната кота** | **React Three Fiber** (декларативно) | Сцена с интерактивными зонами, а не высокопроизводительный раннер. R3F идеален: `<Canvas><ambientLight /><CatModel /><InteractiveZone />...</Canvas>` |

**«Подводный камень»**: Matter.js и R3F в одном проекте — это ок, они не конфликтуют. Каждый живёт в своём контейнере. Но НЕ пытайтесь вставить Matter.js-физику в R3F-сцену — держите их изолированными.

### План установки:
```bash
bun add matter-js
bun add -D @types/matter-js
# R3F и Drei уже установлены — просто начните использовать
```

## «Подводные камни» и риски

| Риск | Решение |
|------|---------|
| **God-hook `useGameState`** при росте | Постепенно вытеснять адаптерами, не ломая работающий код |
| **R3F на слабых Android** | Использовать `InstancedMesh`; ограничить FPS до 30 на mobile; комната кота — статичная сцена, нагрузка низкая |
| **Matter.js не для 3D** | Держать 2D и 3D сцены в отдельных DOM-контейнерах, не смешивать |
| **AI-задачи могут галлюцинировать** | Валидировать JSON Schema на клиенте перед показом; fallback на локальный генератор |
| **Capacitor и WebGL** | Capacitor WebView поддерживает WebGL, но проверить на реальных устройствах низкого сегмента |
| **Размер бандла** | Three.js (~500KB gzip) + Matter.js (~80KB) = допустимо для PWA, но следить через `vite-plugin-visualizer` |
| **Миграция данных localStorage** | При изменении структуры ФГОС — написать мигратор (версионированные ключи `kot_ucheniy_v16`) |
